## 4. Findings и исправления

### F1 — P1: lowering теряет смысл, а validator не подтверждает полноту

Источники: [topology-tools/plugins/compilers/security_plan_compiler.py#L150](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/topology-tools/plugins/compilers/security_plan_compiler.py#L150), [topology-tools/plugins/validators/security_plan_validator.py#L61](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/topology-tools/plugins/validators/security_plan_validator.py#L61).

1. `_lower_one` выбирает `sorted(ports.items())[0]`. Воспроизведение с `ports={tcp:[53], udp:[53]}` даёт только TCP, при этом `unlowerable=[]`. Это не диагностируемое ограничение, а тихая потеря части правила. Для permit это потеря доступности; для deny — потеря ограничения.
2. На реальных overrides compiler публикует 2 scopes, 7 rules и 3 unlowerable. Среди последних — `servers-to-management-deny`. Передача этого payload через registry в validator даёт SUCCESS без diagnostics.
3. Validator принимает пустой `rules` при непустом `scopes`, terminal с `effect=permit` и два permit с одинаковой position. Все три случая проверены отдельными in-memory probes.
4. Scopes compiler выводит из успешно lowered rules. Полностью непредставимый scope может исчезнуть из исполняемой части.

**Изменение:** typed transport predicates, явный whole-zone/any-transport deny отдельно от пустого selector; один исходный selector может давать несколько правил. Не чинить общий deny перечислением известных service ports: это ослабляет исходное ограничение.

Ввести явные completeness/readiness и независимый expected scope inventory. Частичный shadow plan разрешено исследовать, но запрещено передавать в strict rendering/activation. Validator должен проверять: schema, обязательные scopes, полное покрытие исходных требований, unresolved/unlowerable, единственный корректный terminal, уникальные последовательные позиции и integrity binding.

**Acceptance:** TCP+UDP сохранены; общий deny выражается или блокирует strict scope; удаление scope/guard, подмена terminal и пропуск правила ловятся независимо от compiler.

### F2 — P1: legacy override пока превращается в permit без strict approval boundary

Источники: [topology-tools/plugins/compilers/security_plan_compiler.py#L173](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/topology-tools/plugins/compilers/security_plan_compiler.py#L173), [topology-tools/plugins/manifests/compilers.yaml#L319](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/topology-tools/plugins/manifests/compilers.yaml#L319), [adr/0118-analysis/IMPLEMENTATION-PLAN.md#L740](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/adr/0118-analysis/IMPLEMENTATION-PLAN.md#L740).

Compiler читает normalized rows/legacy policy_overrides, а не завершённый intent с approved bindings; `action=accept` непосредственно даёт `effect=permit` и `origin=binding:...`. Это допустимо как явно изолированная legacy-characterization проекция, но не как canonical strict plan, который следующим шагом начнёт рендерить W07.

**Изменение:** явно разделить legacy/shadow candidate и validated strict plan. Для strict lowering входом должны быть approved bindings, guards, execution contexts, requirements и provenance из нормализованного intent. Generator/backend compiler не должен принимать candidate payload как разрешение. Исполняемые контексты нужно привязать к enforcer/domain/family/hook/chain: matrix ID сам по себе такой привязкой не является.

**Acceptance:** неподтверждённый legacy override не создаёт strict permit/artifact; добавление capability не создаёт grant; отказ не включает silent legacy fallback.

### F3 — P1: capability composition пока проверяет не всю зависимую систему

Источники: [netmodel/capability.py#L379](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/netmodel/capability.py#L379), [netmodel/capability.py#L267](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/netmodel/capability.py#L267).

Прогресс: независимые evidence kinds, mode/owner/delegation/freshness checks и prerequisite graph действительно появились.

Но freshness/delegation проверяются только для `chosen`, до добавления prerequisites. Probe с выбранным offer, зависимым от просроченного и неделегированного mutating prerequisite, возвращает `[]` conflicts. Одновременно незаявленная aggregate capacity тоже не создаёт finding. Раскрытие catalogue идёт только на один уровень; полноценная транзитивная цепочка не подбирается из catalogue.

Дополнительно: один mode и один owner навязываются глобально всему набору, без resource/subject scopes; это отвергает допустимые независимые компоненты. `content_digest` по-прежнему принимается от caller как непустая строка, а body не хешируется и не сверяется.

**Изменение:** сначала полное транзитивное раскрытие зависимостей, затем проверка каждого выбранного и зависимого узла. Resource-scoped capacity/mode/owner constraints; unknown capacity — unverified. Отдельно semantic strategy selection и evidence assessment; canonical semantic-core digest и отдельно evidence annex. Нельзя считать отсутствие conflict полным satisfaction.

**Acceptance:** трёхуровневые prerequisites, expired/undelegated dependency, unknown capacity, разные независимые owners, одинаковый ID/version при разных реальных bodies.

### F4 — P1: SEC-STATE использует неверную временную базу

Источник: [netmodel/state.py#L150](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/netmodel/state.py#L150).

`age = now_ticks - session.established_at` сравнивается с revocation deadline. В модели нет момента начала отзыва. Давно существовавшая сессия оказывается просроченной сразу после смены epoch, хотя согласованный срок отзыва ещё не прошёл. Probe: established_at=0, now=100, deadline=10 — сразу два survivors. Сам факт начала revocation в tick 100 модель вообще не способна передать.

`Revocation.epoch_id` также не используется для проверки связи с active epoch.

**Изменение:** revoked_at/effective_at или абсолютный deadline, привязанный к переходу epoch; явная проверка old/new epoch. Разделить stale-session grace и новые неавторизованные подключения. Related sessions должны участвовать в фактической проверке родительской авторизации, не только в helper-фильтре.

**Acceptance:** старая сессия до deadline, на границе и после; новые подключения после revocation; обратный трафик; родитель/related; неверный epoch.

### F5 — P1 до подключения deploy: transition oracle не проверяет завершение

Источник: [netmodel/transition.py#L205](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/netmodel/transition.py#L205).

Исправленный replay действительно ловит неправильный порядок. Однако `plan_transition` проверяет только ACCEPT вне envelope на переданных flows/states. Не проверяются достижение new plan, фактические old/new digests, expiry, достаточность flow inventory и итоговая availability. UNSUPPORTED пропускается вместе с DENY.

Probe с пустым flow space/strategy и просроченным envelope с произвольными digests возвращает `[]` без отказа. По коду неполная strategy тоже не обязана довести состояние до new.

**Изменение:** preconditions envelope/digests/time, complete mutation replay, равенство итогового canonical state целевому plan, postconditions AUTH и AVAIL. Unknown execution должен блокировать доказательство. Пока simulator канонически пересортировывает правила на каждом шаге, он не доказывает конкретную последовательность RouterOS/Terraform mutations: это отдельный backend-level test contract.

### F6 — P2: regression/contract gates остаются красными

Источники: [tests/plugin_integration/test_security_matrix_compiler.py#L433](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/tests/plugin_integration/test_security_matrix_compiler.py#L433), [tests/plugin_contract/test_integration_tests_no_legacy_publish_registry.py#L22](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/tests/plugin_contract/test_integration_tests_no_legacy_publish_registry.py#L22).

Три прежних failures: `test_publishes_security_matrices`, `test_missing_zone_ref_emits_error`, `test_matrix_without_zone_refs_emits_warning`. Fixtures не содержат class_ref/lineage, которые нужны текущему class-based selector. Исправить fixtures по контракту normalized rows; не возвращать отбор по префиксу instance ID.

Новый проверенный contract failure: `get_published_data(` в `test_network_intent_resolver_compiler.py` и `test_security_plan_compiler.py`. Перейти на принятые snapshot/envelope test helpers, не отключать contract guard.

### F7 — P2: доказательные заявления и W07 scope требуют уточнения

Источники: [tests/netmodel/test_obligations_against_real_topology.py](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/tests/netmodel/test_obligations_against_real_topology.py), [tests/plugin_integration/test_security_plan_compiler.py#L310](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/tests/plugin_integration/test_security_plan_compiler.py#L310), [adr/0118-analysis/IMPLEMENTATION-PLAN.md#L850](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/adr/0118-analysis/IMPLEMENTATION-PLAN.md#L850), [adr/0118-analysis/W07-BACKEND-SPECIALIZATION-DECISION.md](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/adr/0118-analysis/W07-BACKEND-SPECIALIZATION-DECISION.md).

- Единственный skipped netmodel test — проверка реального guard: deny без ports не представим. Это открытое acceptance obligation, не успех SEC-AUTH над всеми источниками.
- Реальные obligation tests строят reference plan самостоятельно; новый differential сравнивает последовательность origins, не всю semantics или accepted-flow set. Ошибка predicate может сохранить origins и пройти проверку.
- Path coverage принимает Exclusion с owner/reason как достаточную. Для фактически существующего in-scope bypass требуется доказательство disabled/isolation, а не только подписанная причина.
- Фраза, что G3 осталось только расширить в рамках W07, преждевременна: intent→approved plan→independent obligations ещё не соединены полностью.
- Правильная часть W07: backend semantic specialization до validation, в backend module. Но capability-based dispatch сам по себе не flag-as-proof; запрещено выдавать dispatch за qualified satisfaction. Не нужно переносить все 1565 строк projection только потому, что они находятся в generate. Переносить semantic decisions, оставляя форматирование и rendering генератору.
- Line/function budgets полезны как debt inventory, но не доказывают absence of semantic decisions. Нужны executable consumer-contract и mutation tests.
- Governance checks зелёные, но тексты всё ещё расходятся: REGISTER содержит Accepted в таблице и старый Proposed ниже; rules запрещают считать новые shapes валидными вообще, хотя schema/validator уже частично реализованы. Статусы нужно разнести по design acceptance, partial implementation, qualification и activation.

## 5. Рекомендуемая последовательность реализации

### PR1 — восстановить gates и точность статуса

Исправить 3 fixtures и 2 legacy registry accesses. Обновить текущую gate/evidence matrix, не переписывая исторические результаты как новые. Exit: targeted suite и plugin-contract зелёные; открытые/пропущенные обязательства перечислены явно.

### PR2 — закрыть canonical intent/plan contract

Решить F1/F2: typed selectors, approval isolation, complete scopes, execution contexts и source mapping. Разделить shadow diagnostics и strict eligibility. Добавить schema/payload validation и зарегистрированные diagnostics; не придумывать номера вне registry. Exit: полное покрытие approved input или явный блокирующий результат.

### PR3 — подключить независимые obligations к одному pipeline plan

Сравнивать semantic IR и поведение, не только origins. Намеренно удалять guard/UDP/scope, менять effect/context/terminal, нарушать position/digest. Добавить boundary flows вне перечисленных service ports и отдельные scopes. Exit: каждый mutant ловится по своему обязательству, без общей ошибочной нормализации у compiler и oracle.

### PR4 — довести capability/state/transition contracts

Закрыть F3–F5; синхронизировать schema, formal contract и tests. Scope/time/unknown — типизированные данные, а не implicit defaults. G3 не закрывать по одному лишь количеству тестов или наличию восьми модулей.

### PR5 — один ограниченный RouterOS backend slice

После исправленного neutral plan реализовать compile-stage specializer → independent backend validator → render-only generator. Зафиксировать точные version/provider/profile, paths и ownership. Не смешивать это с переносом всех projections. W05 overlay/domain divergence закрыть отдельным reviewed изменением источников до удаления duplicate zone derivation. Сохранить Terraform post-bootstrap owner; никаких скрытых mutation writers.

Exit: render/parse/interpret differential и двухревизионная artifact parity по контенту с объявленным списком non-semantic exclusions; legacy остаётся отдельным проверенным режимом.

### PR6 — bundle и изолированная лаборатория

Immutable plan/artifact/evidence bindings, preflight, journal, faults, recovery и authorized rollback. Сначала ограниченный scope и TUC, затем qualification. Production activation — отдельное решение человека; не следствие того, что offline tests прошли.
