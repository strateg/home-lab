# Code review ADR0118/0119: 12f4e836

Дата: 2026-09-14. Объём: изменения от 79d2fa8a до 12f4e836, прежде всего compiler, независимый validator, Q и проверки полноты.

## Итог

Прежние исправления реальны: compiler сохраняет TCP+UDP, выражает any-transport, выделяет blocked_scopes и legacy_shadow; validator читает независимый источник и ловит согласованные delete-mutants. Однако несколько новых mutants проходят без error, включая полную потерю явно требуемого потока. PR2 нельзя считать завершённым, а результат validator пока нельзя использовать как достаточное доказательство strict-допуска.

Это дефекты новой модели/доказательства, не установленные нарушения действующего firewall и не утверждение о произведённом deploy.

## Findings

### R1 — P1: объявленное Q может вообще не проверяться

Код: [topology-tools/plugins/validators/security_plan_validator.py:615](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L615), [topology-tools/plugins/validators/security_plan_validator.py:712](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L712).

Два независимых воспроизведения через реальный plugin registry:

1. Источник: any-transport permit z.a → z.b и availability requirement TCP:53. В плане effect исходного permit заменён на deny с сохранёнными origin/transport. Результат validator: **SUCCESS, diagnostics=[]**. `_flow_space` использует permits/guards и plan, но не availability. Для any-transport исходника и такого плана в пробах остаётся только SCTP:64999; требуемый TCP:53 не проверяется.
2. Источник разрешает только TCP:443, но Q требует UDP:53. Исходный план также получает **SUCCESS, diagnostics=[]**. `_check_requirements_are_permitted` проверяет только отсутствие конфликтующего guard, а не наличие permit. Поэтому реализовано Q ∩ D = ∅, но не Q ⊆ A. UDP:53 дополнительно отсутствует в probe space.

Исправление: обязательные потоки независимо включать в проверку либо проверять каждый Q напрямую; для каждого применимого требования проверять полное разрешение с учётом permits и guards. Неподдерживаемый Q не должен исчезать через skip/continue. Противоречивое Q выдаёт source-conflict, а не одновременно SEC-AVAIL failure.

Регрессии: finite Q поверх any permit; Q с портом/протоколом/endpoint, не присутствующим в permits; Q без разрешения и без guard; scope только с Q, без policy overrides.

### R2 — P1: traceable coverage проверяет имя, но не сохранность guard

Код: [topology-tools/plugins/validators/security_plan_validator.py:488](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L488).

Ключ покрытия — `(scope, origin, transport)`. В нём отсутствуют effect, sources, destinations. Источник содержит единственный any-transport guard z.a → z.b. В плане destination меняется на z.a. Validator возвращает только W7002, без E7090 или другой ошибки. Terminal deny сохраняет наблюдаемые deny verdicts и скрывает потерю конкретного обязательного ограничения.

Исправление: связь source requirement → emitted rule должна подтверждать effect и полное покрытие predicates/context, а не совпадение label. Допустимый split/merge проверять как семантическое покрытие, не требованием совпадения числа правил.

Регрессии: изменение endpoints/effect/context при неизменных origin, transport и compiler metadata; guard сужен, а terminal сохраняет все старые verdicts.

### R3 — P1: fixed representatives не гарантируют выход за перечисления

Код: [topology-tools/plugins/validators/security_plan_validator.py:660](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L660).

`64999` и `sctp` — фиксированные значения, а не вычисленные представители дополнения. Существующий тест проверяет их отсутствие только в одной fixture.

Воспроизведение: источник разрешает TCP/UDP/ICMP/SCTP только на 64999. К корректному плану добавлен any-transport permit z.a → z.b. Все исходные правила сохранены, positions корректны. Результат — только W7002, **E7083 отсутствует**, хотя новый permit разрешает, например, TCP:53.

Исправление: детерминированно строить классы эквивалентности по текущим selectors; выбирать представителя вне объединения перечисленных значений. Когда дополнение пусто, не выдумывать несуществующее значение. Не смешивать транспортный порт с ICMP type/code при расширении алгебры.

Регрессии: исходники перечисляют прежний sentinel; почти весь допустимый диапазон перечислен; порядок входов меняется, проверяемые классы остаются теми же.

### R4 — P1: добавленная область не проходит SEC-AUTH

Код: [topology-tools/plugins/validators/security_plan_validator.py:474](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L474), [topology-tools/plugins/validators/security_plan_validator.py:550](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L550).

Coverage ищет только missing source scopes. Семантический цикл идёт только по source scopes. Поэтому план может добавить новую scope с разрешающим правилом и корректным terminal.

Воспроизведение: к корректному плану добавлены `invented-scope`, any-transport permit и terminal, использующие уже известные z.a/z.b. Validator возвращает только W7002. Endpoint closure не помогает, поскольку endpoints известны; новую область никто не проверяет по авторизации.

Исправление: проверять обе разности source/plan scopes. Необъявленная scope должна отвергаться; производные backend scopes допустимы только с явной проверяемой привязкой к исходному execution context. Пустой источник также не должен автоматически оправдывать произвольный непустой план.

Регрессии: extra scope с permit, extra scope только с terminal, неизвестный endpoint при пустом declared endpoint set, подмена matrix/execution context.

### R5 — P1: отказ от unsupported semantics реализован только частично

Код: [topology-tools/plugins/compilers/security_plan_compiler.py:268](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/compilers/security_plan_compiler.py#L268), [topology-tools/plugins/validators/security_plan_validator.py:400](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/topology-tools/plugins/validators/security_plan_validator.py#L400).

Проверены три случая:

- `ports={tcp:["1000-2000"]}`: compiler правильно блокирует scope. Но validator повторно делает `int("1000-2000")`, падает с ValueError и возвращает generic **E4102**, а не E7094. Независимый parser не получил защиту compiler parser.
- `ports={"!tcp":[22]}`: compiler блокирует scope; validator трактует !tcp как обычный protocol и выдаёт E7093 missing permit вместо диагностики unsupported semantics.
- `ports="tcp:443"`: compiler считает не-Mapping отсутствующим transport и выпускает **any-transport permit**, blocked_scopes пуст. Validator делает то же преобразование и не выдаёт error. Это общий неверный fallback, который согласие двух реализаций не обнаруживает.

В проверенном validator нет emit E7094; тесты unsupported selectors проверяют compiler output, но не прогон compiler → validator. Регистрация кода не означает наличие его владельца в runtime.

Исправление: различать отсутствие поля и неверный тип; валидировать и source payload, и plan payload до интерпретации. Обе независимые реализации должны отвергать неизвестную семантику, не делить ошибочный parser и не сводить повреждённый ввод к any. Добавить structured diagnostic вместо исключения. Уже заблокированная scope не должна приводить к аварии проверки остальных scopes.

### R6 — P2: snapshot коммита не воспроизводится с его framework.lock

Код: [projects/home-lab/framework.lock.yaml:10](//wsl.localhost/NixOS/home/nixos/workspaces/home-lab/build/review/12f4e836/projects/home-lab/framework.lock.yaml#L10).

На изолированном tracked snapshot оба `task netmodel:snapshot` и `task framework:verify-lock` завершаются ошибкой E7824:

- lock: `sha256-fab9643208f875e1aba648c722284cec00faf9fb28bcaf9de844b141e35fd931`;
- computed: `sha256-849f84f0091c05ad4e461c4077eb2a501d889cb04b2572dce49dbb5d4e378f48`.

Исправление: обновлять lock после последних framework changes и проверять из чистого checkout. Старый effective.json не использовать как доказательство проверки текущего коммита.

## Порядок исправлений

1. R1: сделать Q действительно проверяемым и обеспечить Q ⊆ A.
2. R2/R4: закрыть semantic coverage guards и namespace scopes.
3. R3/R5: замкнуть поддерживаемую алгебру и доказать полноту представителей; error cases проверять полным compiler → validator вызовом.
4. Восстановить чистый lock/snapshot и полные reference-тесты. Не закрывать G3 по числу зелёных unit tests.
5. После этого использовать verification в strict-admission. Саму границу можно разрабатывать параллельно, но positive admission нельзя основывать на текущем SUCCESS, который пропускает показанные ошибки.

Новая strict-граница ещё не входила в проверенный коммит. Старые F3–F5 по capability composition, временной базе SEC-STATE и завершению transition этим PR также не закрыты: соответствующие модули в рассматриваемом диапазоне не менялись. Их повторный полный аудит — отдельная работа.
